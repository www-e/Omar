POST-WAVE FIX — GLASS/BLUR WAS DEAD IN PRODUCTION
  Found by the Showreel agent's note that the computed backdrop-filter
  resolved to "none", then confirmed against the production build.
  CAUSE: the source wrote BOTH
      backdrop-filter: blur(8px);
      -webkit-backdrop-filter: blur(8px);
  The build's CSS minifier folds that pair down to the PREFIXED form only.
  Modern Chrome (156, the version actually shipping here) no longer supports
  -webkit-backdrop-filter:
      CSS.supports('-webkit-backdrop-filter','blur(8px)') -> false
      CSS.supports('backdrop-filter','blur(8px)')      -> true
  So the blur never rendered. Measured before the fix:
      .vimeo-hero__btn         backdropFilter: none
      .magnetic-cta__btn--ghost backdropFilter: none
      .showreel__chip          backdropFilter: none
      .showreel__chip-btn      backdropFilter: none
      (.nav-links kept both because its source only declared the standard
       property — the minifier adds the prefix itself when the targets need
       it, and that is the correct way to write it.)
  The duplicate pair was PRE-EXISTING in the original site (.vimeo-hero__btn)
  and the two new components copied the same pattern.
  FIX: drop the redundant -webkit-backdrop-filter line, keep only the standard
       property, in app/styles/showreel.css (x2), app/styles/magnetic-cta.css,
       app/styles/vimeo-hero.css.
  AFTER the fix, in the rebuilt production CSS:
      4x backdrop-filter:blur(8px) + 4x -webkit-backdrop-filter:blur(8px)
      computed backdropFilter = blur(8px) on all four rules
  AUDIT of every other prefixed property in the source CSS (base.css,
  footer.css, navbar.css, page-loader.css, projects.css, responsive.css):
  background-clip and user-select keep both forms, -webkit-appearance was
  standardized to appearance, -webkit-line-clamp is the legacy clamp and
  still intact. backdrop-filter was the only one measurably broken.
